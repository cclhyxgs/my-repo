# 「技术指标参数库」独立配置页面 — 实施方案

## Summary
用户提出「初级模式技术指标参数配置不应该另起一个页面吗」。当前技术指标（RSI / 均线 / MACD / 布林 / KDJ / ADX / ATR / 量比等）的**计算参数**是从高级模式的因子配置（`factor_configs.<因子>.params`）里派生的，其中若干为硬编码默认值。初级模式下因子已休眠、因子管理 Tab 隐藏，但技术指标看板、状态分界的技术信号 AND 条件、仓位分级判定仍依赖这些参数 —— 初级用户**看不见也改不了**，参数却真实影响判定。这是缺口。

本方案新增一个**独立的「技术指标参数」配置窗口**，从原软件「功能入口」按钮触发（Toplevel 弹窗风格，与自选股诊断/全市场分析等并列），存放独立配置节点 `tech_indicator_params`，初/高级两模式共用同一来源；未配置时回退当前因子派生值，**存量行为零回归**。

## Proposed Changes

### 1) 配置数据：`tech_indicator_params` 节点
在方案 json（scheme config）新增扁平节点：
```json
"tech_indicator_params": {
  "ma_base": 20, "rsi_period": 14,
  "macd_fast": 12, "macd_slow": 26, "macd_signal": 9,
  "bb_period": 20, "bb_std_dev": 2.0,
  "kdj_period": 9, "adx_period": 14, "atr_period": 14,
  "volume_ratio_period": 20
}
```
- **q：** 全部跨周期生效一套；不按方向拆分（技术参数与多空方向无关）。
- **为什么会这样设计：** 独立于因子配置，初级用户无需碰因子管理即可调技术参数；高级用户也可集中覆盖原来藏在因子 params 里的技术参数。
- 说明：`bb_std_dev` 为浮点（BollingerAnalyzer.calc 已支持 `std_dev=2.0`），其余为 >=2 的整数。

### 2) 后端 getter（quant_config.py）
新增：
```python
def get_tech_indicator_params():
    c = _cfg().get('tech_indicator_params')
    return c if isinstance(c, dict) else {}
```
贴合现有 `get_veto_params` 风格，改动最小。

### 3) 引擎读参统一决策（scoring_core.py）— 优先新节点，回退因子/默认
在 `build_tech` / `build_market_dict` 顶部把技术参数解析集中成一次读取，`_cache_tech_params()` 返回一个 dict（新节点覆盖 → 因子派生 → 默认值，优先级如上），再让各调用点使用该 dict：

新增解析函数：
```python
def _tech_params():
    """优先级：tech_indicator_params 新节点 > 因子派生 > 默认。缓存于函数局部。"""
    node = quant_config.get_tech_indicator_params() or {}
    def _i(k, factor, fkey, default, cast=int):
        if k in node and isinstance(node[k], (int, float)):
            v = cast(node[k])
            return v if (cast==int and v>=2) or cast!=int else default
        # factor 派生
        fv = _get_factor_period(factor, _get_factor_param(factor, fkey, cast(default)))
        ...
    return {...}
```
**简化红线（避免过度工程）：** 不重写每个读取点的语义，只把 `build_tech`/`build_market_dict` 中 8 组参数改由该字典取值，函数签名/返回值一律不变：
- `build_market_dict`：`vol_period` 与 `judge_arrangement` 基础周期改用 node `volume_ratio_period` / `ma_base`（回退现有 factor 逻辑）。
- `build_tech`：`_vol_period`/`_adx_period`/`_atr_period`/`_bb_period`/`_kdj_period`、`rsi_period`、`_m_fast/_m_slow/_m_sig`、`_bb_std_dev` 分别改从解析结果取；`BollingerAnalyzer.calc(closes, period=_bb_period, std_dev=_bb_std_dev)`。
- `create`/`compute_stock_score` 的 `rsi_period=None` 默认读取路径保持（node 空时仍走 `rsi_value`）。

> 备注：`calc_all_ma` 的 6 档硬编码由 `judge_arrangement` 的 `ma_base` 间接驱动（档位=派生），不改 `calc_all_ma` 本身；如需暴露固定 6 档 MA 周期属后续增强，本方案不纳入（保持 `ma_periods(base)` 派生态）。

### 4) 前后端映射（config_mapper.py）
- `_default_quant_data`：新增 `tech_indicator_params` 节（含上表全部键+默认值），供 UI 渲染初始值。
- `_config_to_quant_data` / `_quant_data_to_config`：增加 `tech_indicator_params` 往返同步（缺失时用默认值补齐；非 dict 忽略）。
- `_validate_quant_before_save`：对技术参数做数值合理区间校验（int>=2，`bb_std_dev`>0），与现有 `_validate` 表格式一致。

### 5) 前端独立窗口（ui_mockup/index.html）
- 在「功能入口」新增按钮「技术指标参数」，打开一个 Toplevel 风格弹窗（独立 div #techParamsWin），不并入模型配置弹窗的 8-Tab，也不改主窗口 3-LabelFrame+Tab 结构 —— 契合「反对信息架构变更、按 Toplevel 弹窗扩展」约束，也最贴近「另起一个页面」。
- 窗口按 8 个参数分组渲染成表单（组标题 + 数值输入），绑定 `quantData.tech_indicator_params`：
  - 均线：基础周期
  - RSI：周期
  - MACD：快线/慢线/信号
  - 布林：周期/标准差
  - KDJ：周期
  - ADX：周期
  - ATR：周期
  - 量比：周期
- 底部「保存/取消」：保存走现有 quantData → config 保存往返（与模型配置弹窗共用同一 `saveQuant` 链路，方案随当前方案持久化）；保存后调用 `refreshStatusBar()` 保持状态栏一致。
- **模式门控：** 两模式均可见可改（共用配置基座）；初级无需看因子管理即可进入此窗口调整技术参数。不改现有 `html[data-usage]` 门控逻辑。

## Assumptions & Decisions
- **入口位置**：独立弹窗、功能入口触发（默认；用户未确认时我选择此方案，因最贴近「另起一页」且不破坏模型配置 8-Tab 结构）。若用户更想要「模型配置新增第 9 个 Tab」，可改第 5 步，数据/引擎改动不变。
- **来源统一**：`tech_indicator_params` 节点优先，空则回退因子派生 → **高级模式在『高级=完整因子精细化』下仍可用因子 params，初级在『因子休眠』下可用新节点配置技术参数**，两者不冲突。
- **范围裁剪**：只暴露能改动且引擎确实消费的参数（上表 11 键）；指标阈值（如 RSI<70、量比>1）属「状态分界/否决项」配置，不在此页面重复。
- **不做**：不新增固定 6 档 MA 输入、不对 `calc_all_ma` 动刀、不改模型配置弹窗 8-Tab、不加因子化评分绑定。
