## 0. 文档说明

### 0.1 范围

覆盖 M-Bull 桌面端 v2.0（PyWebView 形态）的全部可观察功能：启动与系统、行情与 K 线、个股量化分析、自选股批量诊断、全市场扫描与板块强度、量化模型配置（方案/因子/回测/幽灵规则）、监控、通知、数据源、执行与复盘闭环（纪律账本）、情绪账本、快速起步向导、授权管理、关于/帮助、用法模式，以及系统级行为（日志/崩溃/单实例/打包）与数据/回测层规格。

### 0.2 术语

| 术语 | 含义 |
|---|---|
| 方案（Scheme） | 一组完整可保存的量化配置（因子、权重、阈值、仓位、信号、风控等），绑定市场/方向/周期 |
| 因子预期分（stock_score） | 纯个股因子计算分（z-score→方向→截断→IC加权→冲突惩罚→钳制），整数 0~100 |
| 最终分（final_score） | 融合市场环境后的分（clamp(w·stock+(1−w)·market)），供入场四档阈值判定 |
| 触发建仓等级（entry_tier） | 强势/标准/试探/观望/博反弹/恐慌反转/弱势 七档，由 StockClassifier 输出 |
| 星级 | 由 tech_strength 绝对映射（0.2/0.4/0.6/0.8 分界）的 1~5 星 |
| 冷却期 | 连续亏损触发后禁止记纪律信号的全局状态 |
| 信号 | 单只诊断（含监控触发的诊断）产出的建仓/清仓参考记录，写入纪律账本 |
| 情绪化差 | 信号未执行/情绪操作造成的虚拟盈亏（"没赚就是亏，没亏就是赚"） |

### 0.3 关键约束（合规红线）

- 信号评级仅描述技术面强度（确定性），**不给出任何仓位/买卖建议**：`engine/signal_rating.py` 的 `_ACTIONS` 注释明确该约束，UI 文案禁止"建议加仓/不加仓"等表述，只展示引擎输出的 narrative/strategy（`engine/signal_rating.py:17-18`）。
- 界面文案全中文，不暴露内部英文枚举（例外：因子注册表显示名 RSI/ATR/OBV 等英文 label）。
- 免责声明：产品定位"技术分析工具"，不构成投资建议。
- **信号来源硬约束**：信号只从「单只诊断/期货诊断/监控」三处产生，**全市场扫描不落信号**（见 F-11xx）。

## 1. 产品定位与合规口径

**量化分析辅助工具**（非交易执行工具）：把用户自己的交易模型程序化为「方案」，对个股/期货输出因子预期分、星级、触发建仓等级、加减仓/清仓信号，并提供回测验证、全市场扫描、自选股批量诊断与「执行与复盘」纪律闭环（情绪账本）。**不接实盘、不下单，决策权保留在用户。**

定位与合规口径见 `docs/工具评测_用户视角.md`、`docs/使用说明书.md`。工具定位为「帮助散户克制情绪化交易」的"刹车"，核心任务是证明纪律值多少、用户偏了多少。

关键事实：

- **单 UI 形态**：仅 PyWebView（`main_webview.py` + `build_webview.spec`）；根目录无 `main.py`，亦无 Tkinter 版的 `build_app.spec`（两者经源码盘点确认均不存在）。Tkinter 版已删除，删除时点记为 2026-08-21——仓库无版本历史可溯，该日期无法由源码复核。**来源：规格编写时的项目记忆，未经源码复核。**
- **前后端桥接**：前端按**位置参数**调用 `window.api.*` / `pywebview.api.*`（`ui_mockup/index.html` 全清单见 §6）。
- **无 HTTP 服务**：WebAPI 为 pywebview 直接注入对象，非网络接口；所有"任务进度"为前端 1.5s 轮询 + 后端进程内 dict。

**引擎评分链**（工作区版）：`factor_tech → scoring_core → score_calculator_v2 → unified_scorer → unified_entry_logic → trading_pipeline`；辅助模块 `indicators/indicators_advanced/factor_registry/veto_registry/stock_classifier/signal_rating/add_engine/reduce_engine/ghost_engine/market_gate/trading_context`。

**报告层与全局状态**（评分链下游，非评分环节）：

- `engine/report_builder.py`（v8.3，1679 行）——报告构建器，评分链的**输出渲染层**：
  - `compute_decision(ctx)`（L40）：建仓裁决**单一真相源**，产出 `DecisionResult`（L23，`__slots__ = entry_levels/verdict/position/badge_text/hit_line_name`）并缓存到 `ctx.decision`。verdict 取值 `'hit'`（命中建仓线）/`'rebound'`（博反弹）/`'wait'`（观望）/`'none'`；初级模式（`get_usage_mode()=='basic'`）走因子休眠分支，只用技术条件建仓/空仓观望文案。
  - `ReportBuilder.build(ctx)`（L955/L977，静态方法）：渲染**全文报告文本**——持仓报告 7 板块（今日操作/持仓评估/决策依据/多空信号/条件预案/幽灵规则/冲突裁决）、空仓决策报告 6 板块（今日操作/因子预期分/决策依据/多空信号/关键价位/建仓条件），返回单个字符串。
  - 调用链：`trading_pipeline.py:263 ctx.decision = compute_decision(ctx)`（流水线内算一次）→ `ui/web_api.py:982 'report_text': ReportBuilder.build(ctx)`；`ui/web_api.py:638` 另在 `_build_report_data` 内复用 `compute_decision`。无流水线路径（测试/回测）由 `build` 内 `if ctx.decision is None` 惰性兜底。
- `engine/state.py`——全局内存态（AppState 单例 + K 线内存 TTL 缓存），详见 §8.4.2。

### 模块一：启动与系统（F-1xx）

#### F-101 单实例锁
- 行为：`CreateMutexW("Global\\M-Bull-SingleInstance")`，已存在则弹「M-Bull 已在运行」并退出（`main_webview.py:329-349`）。
- 目的：防多实例争用 `%LOCALAPPDATA%/M-Bull` 配置文件（曾致 WinError 5 打包失败）。

- WARNING+ 日志/线程异常/warnings 统一落盘 `%LOCALAPPDATA%/M-Bull/logs/M-Bull_error.log`（`engine/error_log.py`，`main_webview.py:153-158`）。

#### F-103 前端 JS 异常上报
- `window._js_error({msg,url,line,col,stack})` → 后端 `_js_error()`（`ui/web_api.py:6077`），面板 `#jsErrorLogBox` 可查看（`ui_mockup/index.html:2015-2024, 4638-4644`）。

#### F-701 回测模式
`start_backtest(params)`（`ui/web_api.py:5641`）支持 5 种 `mode`：

- `futuresic`：期货因子 IC 回测。

- `BacktestLauncher().start(mode, cfg, run_params)` → 返回子进程 task_id（L5757-5758）；`self._backtest_tasks[task_id] = {launcher, mode, prefix, hold, start_time, logs, done, error}`（L5759-5768）。

- 现有 profile 共 **2 个**：`stock`（有数据，被当前激活方案引用）、`futures`（**空壳**：三字段分别为 `[]` / `{}` / `{}`）。方案经 `factor_profile` 字符串引用 profile 名；当前 `current_scheme="1"`（`_meta={market:stock, direction:short, period:日K}`）引用 `stock`，两个期货方案（`期货_多单` / `期货_空单`）引用 `futures`。

```json
"factor_profiles": {
  "stock": {
    "active_factors": ["rsi_value", "macd_hist_norm", "kdj_signal", "ma_arrangement",
                       "volume_ratio", "obv_trend", "pattern_reverse", "fib_position", "pivot_distance"],

                    "score_min": -100, "score_max": 100}

  "futures": {"active_factors": [], "factor_configs": {}, "score_scale": {}}
}
```

- `factor_configs` 内单个因子的**完整字段（实测 7 键，21/21 因子齐备）**：`weight` / `direction` / `params` / `stats{mean,std}` / `ic` / `ic_ir` / `ic_weighted_value`。
  - **无 `name` 键**——因子名即 `factor_configs` 的字典键。
  - `ic` / `ic_ir` / `ic_weighted_value` 为 IC 回测回写的只读元数据（由 `save_factor_stats` 写入，见 §8.3.4）；未回测时为 `null`（实测 `ic_weighted_value` 21/21 全为 `null`）。
- 真实因子完整样例（`factor_profiles.stock.factor_configs.rsi_value`，原样引用）：

```json
"rsi_value": {
  "weight": 0.08944954491554538,
  "direction": 1,
  "params": {"period": 14},
  "stats": {"mean": 50, "std": 15},
  "ic": null,
  "ic_ir": null,
  "ic_weighted_value": null
}
```

- `params` **因因子而异**（非统一结构）：`{"period": N}`（`rsi_value` / `kdj_signal` / `adx_trend_strength` / `atr_norm` / `bb_bandwidth` / `volatility_cone` / `di_spread`）、`{"period":20,"lookback":5}`（`ma_slope`）、`{"period":20}`（`ma_arrangement` / `bias_value` / `relative_strength_20d`）、`{"fast":12,"slow":26,"signal":9}`（`macd_hist_norm`）、`{"period":5}`（`volume_ratio`）、`{"ma_period":10}`（`obv_trend`）、`{"lookback":250}`（`current_drawdown`）、`{"lookback":120}`（`fib_position`）、`{"bins":50}`（`chip_concentration`）；形态类 `pattern_reverse` / `doji` / `pivot_distance` 与 `volume_price_signal` 为空 `{}`。
- `active_factors` 实测 **9 个**（`rsi_value` / `macd_hist_norm` / `kdj_signal` / `ma_arrangement` / `volume_ratio` / `obv_trend` / `pattern_reverse` / `fib_position` / `pivot_distance`）；`factor_configs` 存**全部 21 个**（未启用的 12 个同样带完整 `weight` / `direction` / `params` / `stats` 键）。
- **与 §5.1 上方现有描述的差异（3 处）**：
  1. 上方 `factor_configs` 示例含 `name` 键 → 实测**不存在**；
  2. 上方示例漏列 `ic_weighted_value` → 实测存在（21/21）；
  3. 上方 `score_scale` 示例值 `{weight_multiplier:1.0, z_truncate_min:-3.0, z_truncate_max:3.0, score_min:0.0, score_max:100.0}` → 实测 `stock` profile 为 `{weight_multiplier:30, z_truncate_min:-3, z_truncate_max:3, score_min:-100, score_max:100}`（`score_min` 实测为负、`weight_multiplier` 实测为 30）。

## 8. 回测与数据层规格

### 8.1 回测子进程协议

#### 8.1.1 argv 参数（backtest_cli.py:33-50）
`--config`（临时 config JSON）/ `--mode`（`strategy|scoreic|factoric|futures|futuresic|refresh`）/ `--progress`（进度 JSONL）/ `--cancel`（cancel flag）/ `--offline` / `--dry-run` / `--backtest-cli`（哨兵）。

#### 8.1.3 与父进程通信通道
| 通道 | 文件 | 方向 | 说明 |
|---|---|---|---|
| config JSON | `bt_{taskid}.config.json` | 父→子 | 父写子读（backtest_launcher.py:105-106） |
| 进度 JSONL | `bt_{taskid}.progress.jsonl` | 子→父 | 子写父按字节偏移增量读（backtest_protocol.py:69-70、backtest_launcher.py:154-190） |

#### 8.1.4 进度上报协议（backtest_protocol.py:136-193）
`ProgressWriter` 向 `{tmp}/bt_{taskid}.progress.jsonl` 追加 JSONL，事件类型 `log|done|cancel|error`；父进程 `read_progress()` 按字节偏移增量读取；内部日志经 `progress_cb(line)` 转发。

#### 8.1.5 取消与超时
- 跨进程取消：`FlagFileEvent` 文件存在即事件状态（兼容 threading.Event）（backtest_protocol.py:107-133）；`launcher.stop()` 写 cancel flag（backtest_launcher.py:195-203）。
- 检查点：backtest.py:664、736、factor_ic_backtest.py:103、147；取消后 CLI 写 `cancel` 事件并 `sys.exit(ExitCode.CANCELLED)`（backtest_cli.py:183-185）。
- `launcher.kill_tree()`：优先 psutil 递归 kill；未装时 Windows `taskkill /T /F /PID`、POSIX `killpg SIGKILL`（backtest_launcher.py:231-295）；CLI finally 兜底 `active_children()` terminate（backtest_cli.py:193-199）。
- 7 天临时文件轮转 `ROTATE_SEC = 7*24*3600`（backtest_launcher.py:40-59）。

#### 8.2.2 逐日模拟主流程
```text
preload_all_data() 预加载股票日线缓存 → 生成采样日期序列 → 逐日计算 up_ratio → 每只股票评分+分类+未来收益 → 保存结果
```
- `preload_all_data()`：先磁盘缓存，未命中按腾讯前复权逐只抓并写缓存，offline 跳过未命中；预构建日期→索引映射（backtest.py:509-563）。
- 采样日：按 `sample_interval` 步进，`start_date`→`end_date`；交易日历取 `trade_time`（backtest.py:607-619）。
- 市场宽度：`calculate_up_ratio(date)` 逐只比较当日 close 与前一日 close（backtest.py:565-580）。
- 评分+分类：`_bt_compute_score_classify()` → `scoring_core.compute_stock_score()` → `UnifiedEntryLogic.check_entry()` → `StockClassifier.classify()`（backtest.py:1103-1179）。
- 未来收益：`_get_future_return(df, date, days)` 取第 days 天收益（backtest.py:1182）。
- 并行：`_scan_date_parallel()` 用 `ProcessPoolExecutor` 常驻池按股分片，失败回退串行（backtest.py:641-659、719-755）。

| 策略净值曲线 CSV | `reports/{prefix}_equity.csv` | backtest_runner.py:133 |

### 9.2 迁移建议

> 本节结论已按 H5 可行性分析（`docs/h5-feasibility.md`）回源码核验后修订；原三条建议中第 2、3 条不成立，已改写。

- **服务端化（成立，且为必要）**：引擎纯 Python 无平台硬编码（`engine/*.py` 实测 22279 行），可在服务端托管计算。**但"前端 Web 化后 Android 走 WebView 壳即可复用"不成立**——前端有 26 处 `pywebview.api` 调用（关键桥接点 5 处：`ui_mockup/index.html:6520/7781/7798/7821/7836`）与 1 处 `os.startfile`（`ui/web_api.py:6073`）必须替换为 HTTP/WS；且 Python 引擎无论如何都必须上后端，WebView 壳不能替代后端。**服务端必须锁依赖版本**（`requirements.txt`：`pandas==3.0.3` / `numpy==2.5.1` / `matplotlib==3.11.0` / `cryptography==49.0.0`），否则 pickle 缓存与浮点结果会漂移（`engine/data_layer.py:628-641` 已记录跨 pandas 版本 pickle 不兼容）。
- **数据层（原"天然跨端、无需改造"不成立）**：源码确实只用 HTTP（`engine/notifiers/channels.py:50/80/108` 的 `requests.post` 等），但**跨端 ≠ 浏览器可直连**——源站（腾讯/新浪/东财）**无 CORS 头**，浏览器直连必被拦；且本地单机低频 vs 服务端集中分发，源站限流会随用户数放大。**必须加一层服务端代理**（详见 `docs/h5-feasibility.md` §4.4 能力 1）。
- **授权（原"针对 Android 设备指纹重做"方向正确但不够）**：Android/iOS 与浏览器一样**无硬件指纹 API**（`uuid.getnode()` 在 `license/license_manager.py:76,139` 的 MAC 取法在任何浏览器环境不可用）。故不是"换设备指纹"而是**改账号 + 服务端设备绑定**（绑定强度低于硬件指纹）；同时额度控制（`can_use`/`consume_use`，`license/license_manager.py:682-802`）**必须改为服务端计量**，否则可被清 storage / 改时间绕过。seal 机制（`license/license_guard.py`）在 H5 无等价物——前端代码必然全量下发，防护目标应改为"核心算法后端托管、不下发"。

### 10.2 授权额度 can_use / consume_use 精确规则（#4）

源码：`license/license_manager.py`（**路径更正：不在 `engine/` 下**；正文或来源索引若写 `engine/license_manager.py` 应更正为 `license/license_manager.py`）。常量定义 L56-58：`FREE_DAILY_LIMIT = 10`、`FREE_TRIAL_DAYS = 7`；锁 L60-61（`threading.RLock`）。

**当前实现**
- **试用期起算点**：`state['first_use_date']`，首次进入 `_can_use_locked()` 且为空时置为当天 `date.today().isoformat()`（L735-738），并同步写注册表 `HKCU\Software\M-Bull\first_use`（写 L671-679 / 读 L659-668；进入时先读注册表兜底防删文件 L731-734）。到期判定 `trial_days = (today - first_use).days`，`trial_days >= FREE_TRIAL_DAYS` 即到期拒绝（L744-752）。
- **额度数值**：常量 `FREE_DAILY_LIMIT = 10`，即**每日免费 10 次**。但该额度的**计数只在「未授权 / 已过期 / 按次用尽」路径生效**；**试用期内不限额**——L754-758 明确 `trial_days < 7` 直接返回 `True`（文案「免费试用（剩余N天，不限次数）」），且不累加任何计数。函数 docstring L686-687（"10 uses/day during a 7-day trial"）为旧描述，与现行实现不一致，以实现为准。
- **can_use 口径**（L682-758）：`can_use()` L682-695 取 `_state_lock` → `_can_use_locked()` L698-758。分支顺序：
  1. `_detect_clock_rollback()`（L701-702）：系统时间较上次运行回拨 > 12h（`_CLOCK_ROLLBACK_TOLERANCE = 12*3600`，L177）→ 拒绝；
  2. `get_license_info()`（L704）取状态；
  3. `tampered` → 拒绝（L707-708）；
  4. `active` → 放行，**不计数**（L711-712）；
  5. `dev_mode` → 放行，**不计数**（L715-716）；
  6. 其余（`unlicensed` / `expired` / `no_uses`）→ 走试用期判定（L719-758）：含当日回拨兜底 `last_seen > today` 拒绝（L724-725）、刷新 `last_seen_date`（L727）；试用期内放行且不计数，超期拒绝。
  **关键：`can_use` 本身不检查 `free_queries_today`，日额度门禁实际由 `consume_use()` 侧兜底（见下）。**
- **consume_use 口径**（L761-802）：`dev_mode` 直接 return（L769-770）；`tampered` 直接 return（L773-774）；
  - `per_use` 且 `active` → 扣按次额度：`uses_remaining = max(0, uses_remaining - 1)`（L777-784）；初值来自激活码 payload 的 `uses`，在 `activate()` 中写入（L489-490）。
  - 状态 ∈ (`unlicensed`, `expired`, `no_uses`) → 计每日免费额度（L787-802）：先判断 `free_queries_date != today` 则**重置 `free_queries_today = 0` 并更新日期**（L792-794）→ **重置规则 = 按自然日**（与运行时长无关）；再做二次检查，`free_queries_today >= FREE_DAILY_LIMIT` 则不再累加（L797-798）；否则 `free_queries_today += 1` 且 `total_free_uses += 1`（L800-801）。
  - **无任何路径实现「试用期内每日 10 次」**：试用期内 `can_use` 恒放行，`consume_use` 也不会累加 `free_queries_today`（该分支仅覆盖 unlicensed / expired / no_uses）。故「10 次/日」在当前实现下只在**试用期已结束且未授权**时才真正生效。
- **原子化**：`try_use()`（L805-818）在同一把锁内合并 `can_use` + `consume_use`，规避 TOCTOU；`can_use`、`consume_use` 各自也独立加锁（L694 / L778 / L788）。
- **与 UI「— / 10 次」的对应关系**：
  - `ui_mockup/index.html:1681` 静态初值 `<span id="licenseUsesText">— / 10 次</span>`；刷新逻辑 `index.html:7615`：`uses_remaining != null` 时显示 `${uses_remaining} / 10 次`，否则显示 `—`。
  - `get_license_info()` 的 `uses_remaining` **仅在 `per_use` 类型且授权有效时非 None**（L631-647 返回实际剩余次数）；时间型授权返回 `None`（L613-619）、到期 / 按次用尽返回 `0`（L604-611 / L633-640）、未授权与 dev / tampered 返回 `None`（L564-571 / L531-537 / L543-549）。
  - 因此：显示为 **`N / 10 次` 只出现在「按次授权」场景**（N = 剩余按次额度）；**其余状态一律显示 `—`**。分母 `10` 是 **HTML 内硬编码的展示常量**，与代码 `FREE_DAILY_LIMIT = 10` 数值偶合，但**并非由该常量下发**（无接口把 `FREE_DAILY_LIMIT` 传给前端）。
  - 状态映射缺口（同一处、只记录不改）：`get_license_info()` 的状态取值集合为 `active / expired / no_uses / unlicensed / dev_mode / tampered`，**不存在 `trial`**；而 `index.html:7606` 的 `statusMap` 与 `index.html:5086-5088` 状态栏气泡均以 `status === 'trial'` 分支渲染「试用中 · 剩 N 次」，该分支为**不可达死分支**（试用态实际走 `unlicensed` → 显示「未激活」/ `—`）。底部说明文案 `index.html:1684`「免费试用7天不限次数，激活后永久授权」与 `can_use` 试用期不限次的实现一致。

### 10.3 period_configs 覆盖边界（#5）

源码：`engine/quant_config.py:249-293`（`_merge_scheme_config`）、`L300-310`（`_deep_merge`）。

**当前实现**——合并为三级，自下而上依次覆盖：
1. **profile 基底**（L268-283）：方案含 `factor_profile` 且 `_MODEL['factor_profiles']` 中存在同名 profile → `merged = copy.deepcopy(profiles[fp_name])` 作基底，再逐键叠加方案内联 `config`；其中**内联的因子键 `active_factors` / `factor_configs` / `score_scale` 一律忽略**（L274-282，因子由 profile 独占，避免 `blank()` 填充的空 `{}` 清空共享因子）；`v is None` 的键跳过（L277-278）。
2. **无 profile 的遗留方案**（L284-285）：直接 `base = cfg`（A 股平铺方案）。
3. **周期覆盖**（L286-292）：**仅当 `period` 为真 且 方案未标记 `_meta.period`** 时，取 `sc['period_configs'][period]`，且须为**非空 dict**，才 `base = _deep_merge(base, po)`。
   - **新模型（每周期 = 独立方案，方案自带 `_meta.period`）不叠加 `period_configs`**（L286-288 注释明确：其 `config` 即该周期配置，叠加会与单周期方案语义冲突）。
   - 因此对带 `_meta.period` 的方案传入 `period` 参数是**静默空操作**：不报错、不合并。

- **优先级**：`factor_profile（基底）< 方案内联 config（覆盖，因子键除外）< period_configs[period]（末层覆盖）`。
- **`_deep_merge` 语义**（L300-310）：两侧均为 dict 时递归合并；**其余类型（含 list）以 override 整体替换**（数组不做元素级合并，配置数组需整体重写）。
- 返回前统一过 `_validate_config(base)` 校验（L293）；返回 `None` 表示 scheme 不存在（L260-264）。
- 现状证据：`config/quant_model.json` 各方案未见 `period_configs` 落盘键（与 audit 键级清单一致），该机制当前为**遗留兼容通道，无活跃数据**。

### 10.4 add_params.max_single_position × 总仓位上限 的交叉计算位置（#6）

源码：`engine/add_engine.py`、`engine/quant_config.py`、`engine/backtest_strategy.py`、`engine/backtest_futures.py`、`engine/trading_pipeline.py`、`engine/report_builder.py`、`ui/config_mapper.py`。

**当前实现**
- **配置读取**：`quant_config.get_add_params()`（L1264-1266）返回 `_cfg().get('add_params')` 整体（**不做字段归一 / 白名单**）；`get_risk_params()`（L1272-1274）返回 `_cfg().get('risk_params')`。
- **`add_engine.py` 内部零仓位上限交叉计算**：`AddEngine.suggest_add()` 只产出比例，L328-330 `add_ratio = min(raw_add, max_add)`，其中 `max_add = float(params.get('max_add_ratio', 0.30))`（L61）。**全程不读 `max_single_position`，也不读 `total_position_cap_pct`**；文件头注释 L7「受 max_add_ratio / max_single_position 约束」仅前半段成立。
- **交叉计算实际位于回测层 `engine/backtest_strategy.py`**，分两处、策略不同：
  - **建仓**（L1868-1878）：① `entry_weight = min(entry_weight, self.max_single_position)`（L1870，单只上限）；② 若 `self.total_position_cap_pct < 1.0`，则 `held_weight = Σ total_invested / nav`、`room = max(0, cap - held_weight)`、`entry_weight = min(entry_weight, room)`（L1874-1877）。即**单只上限 ∧ 总仓位剩余空间，取 min**；`entry_weight <= 0` 时跳过建仓（L1881-1882）。
  - **加仓**（`_clamp_add_invested()` L890-905）：**仅受单只上限约束，显式豁免总仓位上限**（L891、L895-897 注释：总仓位上限只限制初始建仓，加仓可动用预留现金，否则总仓到顶后加仓信号永远无法成交）；超限时夹紧为 `max(0, max_single_position * nav - pos.total_invested)`（L903-904）；现金约束由调用点另行校验（L897）。
  - 参数取值（L803-805）：`rp = quant_config.get_risk_params() or {}`、`self.max_single_position = rp.get('max_single_position', 0.30)`、`self.total_position_cap_pct = rp.get('total_position_cap_pct', 0.80)` —— **两个上限均取自 `risk_params`（非 `add_params`），回退默认 0.30 / 0.80**。
  - 期货回测同源读取：`engine/backtest_futures.py:389` `rp = _QC.get_risk_params() or {}`。
- **实盘 / 报告层未实现该交叉计算**：
  - `report_builder.py` 仅把 `risk_params.max_single_position` 当**展示文案**「仓位上限」渲染（L1406-1407、L1537-1538），不参与任何比例运算；L1049 注释亦声明其只作展示。
  - `trading_pipeline.py` 在持仓场景调用 `AddEngine.suggest_add(ctx)`（L239-241）取建议比例，**未与任何仓位上限做二次夹紧**；风控只读 `single_max_loss_pct`（L189）。
  - 全仓检索确认：`total_position_cap_pct` 仅出现于 `backtest_strategy.py`、`tests/`、`config/quant_model.json` 与文档 / 规格生成器，**实盘链路（report_builder / trading_pipeline / web_api）零引用**。
- **配置现状**：`config/quant_model.json` 中 `add_params`（L322-324）**没有 `max_single_position` 键**（只有 `add_tiers` / `max_add_ratio` 等）；`risk_params`（L502-504）含 `total_position_cap_pct: 0.5`、`max_single_position: 0.1`。故题述键名 **`add_params.max_single_position` 在当前仓库数据中不存在**，同名语义由 `risk_params.max_single_position` 承担（与 `audit/03-config-coverage.csv:46` 的 GHOST 判定一致）。
- **UI 位置更正**：两个字段在 UI 上属于**风控参数**分组而非加仓参数——`ui/config_mapper.py:218-220` 的 `'risk'` 数组（及镜像的 `ui_mockup/index.html:3133-3134`），desc 明确「留空 = 不启用」。
- **结论**：#6 的交叉计算**在回测层已实现**（建仓 = 单只上限与总仓位剩余空间取 min；加仓 = 仅单只上限、豁免总仓位上限），**实盘诊断 / 报告层未实现 / 未启用**。
