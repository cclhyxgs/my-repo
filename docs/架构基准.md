# 架构基准文档

> 本文档为产品迭代与代码重构的**核对基准**。所有新需求、改动、重构均须以此为准绳核对，避免偏离打补丁。
>
> 建立日期：2026-08-31（与产品团队多轮对齐后固化）

---

## 1. 产品定位

- **性质**：辅助分析工具，**不接实盘**。系统给到分析与纪律"决策参考"，最终操作在用户手中。
- **买点**：克制情绪化交易。定位为散户在情绪最乱时的"刹车"——把想守但守不住的纪律，做成关键时刻替其执行的东西。
- **客群（两套并行入口，非主次）**：
  - **初级**：吸引炒股新手。低门槛、开箱即用，重技术指标解读。
  - **高级**：给有交易模型的用户。开放因子选股、模型配置、因子分级等专业能力。

---

## 2. 双市场

A股 + 期货**双市场并行**，运行时由 `set_market_type` 在 `'stock'/'futures'` 间切换，`_market_type` **横切整条链**：

| 环节 | 股票 | 期货 |
|---|---|---|
| 品种查询 | `search_stocks` | `search_futures` |
| 行情/分析 | `analyze` | `_analyze_futures` |
| 自选列表 | 自选股 | 自选期货 |
| 诊断报告 | 自选股综合报告 | 自选品种综合报告 |
| 全市场扫描 | A股扫描 | 期货扫描 |
| 回测 | – | `backtest_futures` |
| 状态栏文案 | 已加载 N 只股票 | 已加载 N 个品种 |

"分析 → 触发提醒 → 纪律方案"这条辅助决策链在**每个市场内各自成立**，市场切换是横切在整条链之上的维度。

## 3. 配置基座（初/高级共用）

**核心原则**：技术门槛与否决项是**两个语义层，不可合并**；但两套入口（初级/高级）共用同一套配置基座。

| 层 | 语义 | 优先级 | 可配能力 |
|---|---|---|---|
| **技术门槛（筛选/进级）** | 命中 → 满足/进级 | – | 全指标可选、可 AND、阈值可调、可自定义 |
| **否决项（红灯）** | 命中 → 一票拦下 | **高于一切筛选** | 全指标、阈值可调、可 AND、可增删自定义 |

> 反例警示：不能用"命中即满足 / 命中即拦"的统一引擎。同一个 RSI 既当合格线（>50 才纳入）又当红灯（=90 一票否决），**语义必须分层**。筛选优先于否决，否决优先于筛选——红灯无条件拦下。

### 3.1 技术门槛
- 全指标可选：MA5/10/20/60、RSI、KDJ、MACD、量比、布林、ATR、ADX、乖离、筹码、斐波那契、枢轴等（`tech` 字典已具备）。
- 支持 **AND 组合**（多条件同时命中）。
- 阈值可调、可自定义。
- 向后兼容旧单选枚举（`'none'`/单信号等价于"单条件特例"）。

### 3.2 否决项红灯层
- 原 6 项（写死函数）作废，升级为**可配置红灯集**。
- 内置红灯覆盖 6 大场景，默认全勾选（出厂即有效风控）：
  - 极值/过热：RSI 极端高位、KDJ 极端、乖离率过大
  - 趋势破位：跌破年线、MACD 高位死叉、MA20 拐头向下、20日新高回落、均线死叉
  - 量能陷阱：放量滞涨、高位天量、量价背离
  - 波动异动：ATR 异常放大、跳空高开低走、向下跳空缺口
  - 形态见顶：长上影/吊颈、看跌吞没/乌云盖顶
  - 筹码失守：跌破筹码密集区下沿
- 各项阈值均为可改默认值；支持 AND、可增删、可自定义。
- 空头方向按语义镜像。
- `veto_registry` 现有 6 项作为内置预置红灯保留，兼容旧配置。

### 3.3 两套入口的唯一差异：分级判据
- **初级**：纯技术条件（无因子）→ 技术分级。
- **高级**：因子综合得分 + 技术门槛 → 因子分级。
- 除分级判据外，技术门槛、否决项红灯、配置保存（随方案走）等**完全共用**。

## 4. 各功能：功能门控统一，呈现重心随模式变

**统一原则**：同一功能在两套入口下的**触发能力一致**（功能门控不设两套），差异仅在**呈现重心**（初级重解读、高级重得分/分级）。

| 功能 | 初级 | 高级 | 差异点 |
|---|---|---|---|
| **个股分析** | 指标解读为主轴 | 指标得分 + 因子分级为主轴 | 呈现重心 |
| **自选股诊断** | 完整建/加/减/清 + 解读 | 完整建/加/减/清 + 得分 | 呈现重心（功能统一） |
| **全市场扫描** | **开放**，技术条件驱动排序 | 因子得分排序 | 排序依据 |
| **持仓报告** | 解读 + 持有期纪律为主，侧重风控 | 因子得分 + 分级为主 | 呈现重心（风控双模式重点） |
| **决策卡导出** | 卡片重心=解读看板 | 卡片重心=得分/分级 | 卡片内容重心 |

### 4.1 个股分析
- 初级：主角是**指标解读**——"K线在说什么、该怎么应对"（金叉为什么、RSI 超买怎么办），技术指标看板在主位，因子分/股票类型隐藏。
- 高级：主角是**指标得分**——因子综合得分 + 股票类型 + 因子明细，技术看板辅助（第二道筛选）。
- 同一份分析数据、两种呈现侧重，非两套计算。初级专业感压在"解读质量"上。

### 4.2 自选股诊断
- 两套模式均完整触发**建/加/减/清**信号（功能门控统一，不作降级）。
- 呈现随模式走：初级重解读、高级重得分，与个股分析一致。

### 4.3 全市场扫描
- **开放给初级**（旧"初级禁用"作废）。理由：初级已具备技术条件组合这把"尺子"，排序/筛选依据不再缺失。
- 初级用**技术条件驱动**排序（可 AND），高级用因子得分排序；扫描 ≠ 买入许可，最终是否买入仍由"建仓条件 + 否决项红灯"把关。
- 实现注意：全市场扫描为批量重活，需处理进度/超时/性能。

### 4.4 持仓报告
- 双模式共用的骨架（风控最集中处）：**持有期纪律档位**（加第几档/减到哪档/触发清仓，含触发原因与仓位上限）+ **风控红灯**（命中直接给减/清，一票优先）+ 止损/离场线。
- 初级：解读 + 持有纪律 + 红灯是全工具最需做扎实的地方（散户最易在持有期扛不住/乱加仓）。
- 高级：因子得分 + 分级为主。
- 风控红灯两套入口**同一套**，是"注重风控"卖点的统一防线。

### 4.5 决策卡导出
- 两套入口**共用同一条**导出链路（生成决策卡 → html2canvas 截图 → 存 `decision_cards/`）。
- 卡片内容重心随模式变：初级多放指标解读看板（隐藏因子加减分/共振），高级多放得分/分级。
- 均可导出分享 → 传播 → 说服，反向强化工具价值。

## 5. 分层骨架（重构基准）

- **前端**：`ui_mockup/index.html`（单文件）——UI/交互/门控。UI 信息架构硬约束不变（禁止改造成 SPA 左侧导航）。
- **BFF/API**：`ui/web_api.py` —— 分析/配置/报告/诊断/扫描/监控/复盘等入口。维护成本高（超大单文件），重构优先关注。
- **引擎**：`engine/` —— 评分、仓位、回测、管道、纪律。
- **数据/授权**：`engine/data_*`、`license/`。

**重构三条约定**：
1. 新增归位：新需求默认进对应 `engine/` 模块；`web_api` 不加新方法，只做转发。
2. 收口即删：评分/加减仓/回测改动必须改收口模块（如 `scoring_core`），禁止在别处手抄；改完删冗余块。
3. 把一次性脚本升级为可回归测试，守住"敢删旧代码"的底线。

## 6. 边界与警示（本产品已确立的判断）

- **不接实盘**：无下单、无执行返回，终点是决策参考。
- **技术门槛与否决项分层**，不合并统一引擎。
- **初级 ≠ 阉割版**：三套入口各自完整交付，初级是"技术驱动的风控分级版"。
- **复盘定位**：信号执行纪律画像，仅核算系统发出的信号交易，系统外自由操作不入账。
- **与同花顺差异化**不在选股/预警（同质且合规风险），而在"多股 × 多档位 × 建/加/减/清的完整执行纪律"。
- **模式开关是唯一权威裁判**：所有方案/界面行为服从 `usage_mode`，避免"方案说统一、系统却用因子分级"的错乱。
