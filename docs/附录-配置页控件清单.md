### 1.4 覆盖率自检（q-position）

| 计数项 | 静态 HTML（1461–1525） | 表格行数 | 结论 |
|---|---|---|---|
| `<input` | **4** | P-02、P-03、P-04、P-05 = 4 | ✅ 一致 |
| `<select` | **1** | P-01 = 1 | ✅ 一致 |

**不一致原因说明**：P-07 ~ P-12 **全部**由单一函数 `fillPositionList()`（`index.html:3786-3851`）用模板字符串生成，静态 HTML 中只留下 6 个空容器（`entryPosGrid` 1471 / `marketGateGrid` 1487 / `addTierTbody` 1498 / `reduceTierTbody` 1505 / `reduceTopGrid` 1506 / `riskGrid` 1513）。故静态计数（4+1+1+2+1=9）与表格行数（6 静态 + ~150 动态）不一致属**预期**。
**迁移风险**：任何"按 id 找控件"的静态解析都会**漏掉本页约 94% 的控件**。

### 3.3 ⚠ `ghost_rules.ma_confirm` 是否有 HTML 控件——明确结论

**结论：有。** 三层证据：

| 层 | 事实 | 证据 |

| 1. 控件存在 | 动态生成的 `<select id="ghost-ma_confirm">`，12 个均线选项 | `fillGhostList()` **`index.html:3952`**（模板字符串）；选项源 **`index.html:3147`** / `config_mapper.py:234-235` |
| 2. 写入链路完整 | `setGhostVal` 的字符串分支把值写进 `quantData.ghost[4].val`，`_quant_data_to_config` 再以 `str(v)` 写入 `config['ghost_rules']['ma_confirm']` | `setGhostVal` **`index.html:3964-3967`**（`:3966` `key==='ma_confirm'?val:...`）；`config_mapper.py:866-867` |
| 3. 引擎读取 | `GhostEngine._ma_confirm()` 读 `get_ghost_params().get('ma_confirm','sma_20')` | `engine/ghost_engine.py:41-42` |

**但 `audit/03-config-coverage.csv:43` 与 `audit/00-final-report.md:51` 判其为 GHOST（"无此键"）——两者并不矛盾，指的是不同层面：**

| 层面 | 判定 | 实测 |
|---|---|---|
| **落盘数据现状** | GHOST（"无此键"） | `config/quant_model.json` 全文 `ma_confirm` 出现 **0 次**（实测字符串计数 = 0）；`current_scheme="1"` 的 `ghost_rules` = `{"grace_period_days":3,"profit_threshold":0.5,"add_profit_threshold":3,"rsi_confirm":45}`，**确无 `ma_confirm`** |
| **代码链路** | 完整（非 GHOST） | 见上表 1~3 层 |

**根因（可复现的"显示默认值但不落盘"）：**
1. `quantData.ghost[4].val` 初值 `''`（`index.html:3147`）；
2. `_config_to_quant_data` 回填 `g['val'] = gr.get('ma_confirm','')` → `''`（`config_mapper.py:512`）；
3. 渲染时 `<option ... ${o===(g.val||def)?'selected':''}>`（`index.html:3952`）用 **`g.val||def`** 兜底 → **界面显示 `sma_20`**，但 `g.val` **仍是 `''`**；
4. 保存时 `_quant_data_to_config` 的 `if v != '' and v is not None` 闸门（`config_mapper.py:860`）→ **跳过，不写入**；
5. 只有用户**手动改过下拉**（触发 `onchange` → `setGhostVal`）才会落盘。

**因此**：
- 规格 §5.1（`完整规格_合并版.md:670`）示例中的 `"ma_confirm":"sma_20"` 表达的是**默认值形态**，**不代表仓库落盘现状**；
- 该键的"缺失"是**空值不落盘语义**的结果，属**代码与数据一致的既有设计**，而非写回缺陷（对比 §8.3.5 的 P0 类问题——那类是"用户改了却丢"）；
- 引擎侧 `sma_20` 兜底（`ghost_engine.py:42`）使功能等价，**无功能损失**；
- **H5 迁移注意**：搬到框架后若把 `<select>` 的 `v-model` 直接绑 `ghost_rules.ma_confirm`（缺失 → 空 → 回退第一个选项 `sma_5`），会**改变默认行为**（`sma_5` ≠ `sma_20`）。必须显式保留"空值 → 显示 `sma_20` 但不写入"的语义。
